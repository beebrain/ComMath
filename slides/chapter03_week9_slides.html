Concept 1.1

ลำดับในมุมมองของฟังก์ชัน (Sequence as a Function)

DEF นิยามเชิงคณิตศาสตร์
ลำดับ (Sequence) คือ ฟังก์ชันที่โดเมนถูกจำกัดให้เป็นเซตของจำนวนเต็มบวก $\mathbb{Z}^+ = \{1, 2, 3, \dots\}$: $$\mathbf{a: \mathbb{Z}^+ \to \mathbb{R}}$$ นิยมเขียนสัญลักษณ์ผลลัพธ์ $a(n)$ ด้วย พจน์ที่ $n$ หรือ $a_n$
ANALOGY มโนภาพในชีวิตจริง: สมุดบัญชีเงินฝากรายเดือน
เปรียบเสมือน สมุดบัญชีเงินฝากธนาคาร ที่บันทึกยอดเงินตามงวดเวลา:
• โดเมน ($\mathbb{Z}^+$): คืองวดเดือนที่ $1, 2, 3, \dots$ (ลำดับเวลาที่แน่นอน)
• เรนจ์ ($\mathbb{R}$): คือยอดเงินในบัญชีจริง $a_1, a_2, a_3, \dots$ (เช่น 1,000, 1,500, 2,000 บาท)
ในคอมพิวเตอร์จึงนำมาใช้แทน ดัชนีของอาร์เรย์ (Array Index) หรือภาระงานในแต่ละรอบของลูป
การจับคู่แบบ 1 ต่อ 1 จากงวดเวลา $n$ ไปสู่ยอดเงิน $a_n$

Concept 1.2

ลำดับเลขคณิต (Arithmetic Sequence)

ANALOGY มโนภาพในชีวิตจริง: การออมเงินแบบฝากเพิ่มรายเดือนคงที่
เปิดบัญชีมีเงินตั้งต้น 1,000 บาท ($a_1 = 1,000$) และฝากเงินเพิ่มเดือนละ 500 บาทเท่ากันทุกเดือน ($d = 500$):
• สิ้นเดือน 1: $1,000$ บาท  • สิ้นเดือน 2: $1,000 + 500 = 1,500$ บาท  • สิ้นเดือน 3: $1,500 + 500 = 2,000$ บาท
• สิ้นปี (เดือนที่ 12): $a_{12} = 1,000 + 11(500) = \mathbf{6,500 \text{ บาท}}$ (เพิ่มด้วยอัตราคงที่)
FORMULA การคลี่รูปเพื่อหาสูตรพจน์ทั่วไป
• พจน์ที่ 1: $a_1$
• พจน์ที่ 2: $a_2 = a_1 + d$
• พจน์ที่ 3: $a_3 = a_2 + d = a_1 + 2d$
• พจน์ที่ 4: $a_4 = a_3 + d = a_1 + 3d$
$$\mathbf{\implies a_n = a_1 + (n - 1)d}$$ โดย $d = a_{n+1} - a_n$ คือ ผลต่างร่วม (Common Difference)
PROPERTIES พฤติกรรมและข้อสังเกต
1. ถ้า $d > 0$ เงินในบัญชีเพิ่มขึ้นเรื่อยๆ (Strictly Increasing)
2. ถ้า $d < 0$ มีการถอนเงินคงที่ ยอดเงินลดลงเรื่อยๆ (Strictly Decreasing)
3. ถ้า $d = 0$ ไม่มีการเคลื่อนไหว ยอดเงินคงที่ตลอด ($a_n = a_1$)
4. ใน CS: ใช้คำนวณตำแหน่งหน่วยความจำ `Address = Base + i * Size`

PROBLEM โจทย์ตัวอย่าง

ตั้งสูตรพจน์ทั่วไป: $a_n = a_1 + (n-1)d = 3 + (n-1)(4) = 3 + 4n - 4 = \mathbf{4n - 1}$

$a_{50} = 4(50) - 1 = 200 - 1 = \mathbf{199}$ หรือใช้ $a_{50} = 3 + (50-1)(4) = 3 + 196 = \mathbf{199}$

ตัวอย่างที่ 2 — การหาจำนวนพจน์ทั้งหมดของลำดับ (Find $n$)

PROBLEM โจทย์ตัวอย่าง
กำหนดลำดับเลขคณิต $7, 11, 15, 19, \dots, 83$ จงหาว่าลำดับนี้มีทั้งหมดกี่พจน์?
ขั้นที่ 1
ระบุค่าคงที่ที่ทราบจากโจทย์:
พจน์แรก $a_1 = 7$, ผลต่างร่วม $d = 11 - 7 = 4$, และพจน์สุดท้าย $a_n = 83$ โดยต้องการหาค่า $n$
ขั้นที่ 2
แทนค่าลงในสมการพจน์ทั่วไป:
$$83 = a_1 + (n - 1)d \implies 83 = 7 + (n - 1)(4)$$
ขั้นที่ 3
แก้สมการเชิงเส้นเพื่อหาค่า $n$:
$83 - 7 = (n - 1)(4) \implies 76 = 4(n - 1) \implies n - 1 = \frac{76}{4} = 19 \implies \mathbf{n = 20}$

Concept 1.6

ลำดับเรขาคณิต (Geometric Sequence)

ANALOGY มโนภาพในชีวิตจริง: การเติบโตของเงินลงทุนแบบทบเท่าตัว (Compound Doubling)
ฝากเงินต้น 10,000 บาท ($a_1 = 10,000$) ในกองทุนที่มูลค่าเพิ่มขึ้นเป็น 2 เท่า ($r = 2$) ทุกปี:
• สิ้นปี 1: $10,000$ บาท  • สิ้นปี 2: $10,000 \times 2 = 20,000$ บาท  • สิ้นปี 3: $20,000 \times 2 = 40,000$ บาท
• สิ้นปี 5: $a_5 = 10,000 \times 2^4 = \mathbf{160,000 \text{ บาท}}$ (เพิ่มขึ้นด้วยการคูณทบเท่าตัวต่องวด)
FORMULA การคลี่รูปเพื่อหาสูตรพจน์ทั่วไป
• พจน์ที่ 1: $a_1$
• พจน์ที่ 2: $a_2 = a_1 \cdot r$
• พจน์ที่ 3: $a_3 = a_2 \cdot r = a_1 \cdot r^2$
• พจน์ที่ 4: $a_4 = a_3 \cdot r = a_1 \cdot r^3$
$$\mathbf{\implies a_n = a_1 \cdot r^{n-1}}$$ โดย $r = \frac{a_{n+1}}{a_n}$ คือ อัตราส่วนร่วม (Common Ratio)
INTERPRET ดอกเบี้ยเงินฝากธนาคาร vs CS
• ดอกเบี้ยทบต้น $10\%$ ต่อปี: อัตราส่วนร่วมคือ $r = 1 + 0.10 = 1.10$
• ในคอมพิวเตอร์: การเพิ่มขนาดของ Binary Tree แต่ละชั้น ($r = 2$), การลดขนาดปัญหาใน Binary Search ($r = 1/2$), และการขยายหน่วยความจำ

Concept 2.1

นิยามอนุกรมและสัญกรณ์ซิกมา (Series & Sigma $\sum$)

ANALOGY มโนภาพในชีวิตจริง: ยอดเงินรวมสะสมในสมุดบัญชี (Cumulative Bank Balance)
• ลำดับ ($a_i$): คือยอดเงินที่ฝากเพิ่มในแต่ละเดือน เช่น เดือนที่ 1 ฝาก 1,000, เดือนที่ 2 ฝาก 1,500, เดือนที่ 3 ฝาก 2,000
• อนุกรม ($S_n$): คือ ยอดเงินรวมสะสมทั้งหมดในบัญชี ตั้งแต่เดือนแรกถึงเดือนที่ $n$: $$\mathbf{S_n = \sum_{i=1}^n a_i = a_1 + a_2 + a_3 + \dots + a_n}$$
RULES สมบัติของสัญกรณ์ซิกมา
1. $\sum_{i=1}^n c = n \cdot c$ (ฝากเงินคงที่ $c$ บาททุกเดือน รวม $n$ เดือน ได้ $n \cdot c$ บาท)
2. $\sum_{i=1}^n c \cdot a_i = c \sum_{i=1}^n a_i$ (ดึงตัวคูณร่วมออกนอกซิกมาได้)
3. $\sum_{i=1}^n (a_i \pm b_i) = \sum_{i=1}^n a_i \pm \sum_{i=1}^n b_i$ (แยกบวก-ลบระหว่างบัญชีได้)

Concept 2.5

อนุกรมเรขาคณิตจำกัด (Finite Geometric Series)

ANALOGY มโนภาพในชีวิตจริง: การสะสมเงินออมแบบทวีคูณ (Doubling Savings Plan)
สมมุติวางแผนออมเงินรายสัปดาห์: สัปดาห์แรกออม 100 บาท ($a_1 = 100$) สัปดาห์ถัดไปออมเพิ่มเป็น 2 เท่า ($r = 2$):
สัปดาห์ที่ 1 ถึง 4 ออม: $100, 200, 400, 800$ บาท $\implies$ ยอดรวมสะสมคือ $S_4 = 100 + 200 + 400 + 800 = \mathbf{1,500 \text{ บาท}}$
เมื่อคำนวณด้วยสูตร: $S_4 = \frac{100(2^4 - 1)}{2 - 1} = \frac{100(16 - 1)}{1} = \mathbf{1,500 \text{ บาท}}$ (คำนวณสะดวกรวดเร็ว แม้มีหลายสิบงวด)
FORMULA สูตรผลรวมอนุกรมเรขาคณิต $n$ พจน์แรก
เมื่อ $r \neq 1$: $$\mathbf{S_n = \frac{a_1(1 - r^n)}{1 - r} = \frac{a_1(r^n - 1)}{r - 1}} \qquad \text{(กรณี } r = 1 \text{ จะได้ } S_n = n a_1)$$ • ถ้า $r > 1$ นิยมใช้รูปขวาเพื่อให้เศษและส่วนเป็นบวก
PROOF ที่มาของสูตร (Algebraic Subtraction)
(1) $S_n = a_1 + a_1 r + a_1 r^2 + \dots + a_1 r^{n-1}$
(2) $r S_n = a_1 r + a_1 r^2 + \dots + a_1 r^n$
(1) - (2): $S_n(1 - r) = a_1(1 - r^n) \implies \mathbf{S_n = \frac{a_1(1 - r^n)}{1 - r}}$

ANALOGY มโนภาพในชีวิตจริง: การแบ่งเค้กทีละครึ่ง / กองทุนจ่ายเงินปันผลถาวร (Perpetuity)
สมมุติมีเค้ก 1 ชิ้น วันนี้ตัดกินครึ่งหนึ่ง ($\frac{1}{2}$), วันพรุ่งนี้กินครึ่งหนึ่งของที่เหลือ ($\frac{1}{4}$), วันถัดไป ($\frac{1}{8}$) ต่อเนื่องไม่สิ้นสุด:

CONVERGE กรณีลู่เข้า ($|r| < 1$)
เมื่อ $-1 < r < 1$ จะได้ว่า $r^n \to 0$ เมื่อ $n \to \infty$

DIVERGE กรณีลู่ออก ($|r| \ge 1$)
เมื่อ $r \ge 1$ หรือ $r \le -1$ เช่น ออมเงินเพิ่มเป็น 2 เท่าทุกงวดไปเรื่อยๆ ผลรวมจะโตขึ้นอย่างไร้ขอบเขต
ส่งผลให้ **อนุกรมลู่ออก (Divergent Series)** ไม่สามารถหาผลรวมอนันต์ได้

จำนวนโหนดทั้งหมด $N$ คือผลบวกของทุกระดับตั้งแต่ชั้น $0$ ถึงชั้น $h$: $$\mathbf{N = \sum_{i=0}^h 2^i = 1 + 2 + 4 + 8 + \dots + 2^h}$$ ใช้สูตรอนุกรมเรขาคณิต ($a_1 = 1, r = 2$, จำนวนพจน์ $= h + 1$): $$\mathbf{N = \frac{1(2^{h+1} - 1)}{2 - 1} = 2^{h+1} - 1}$$
EXAMPLE ต้นไม้ความสูง $h = 5$
$$N = 2^{5+1} - 1 = 2^6 - 1 = 64 - 1 = \mathbf{63 \text{ โหนด}}$$
INVERSE ความสูงเมื่อทราบจำนวนโหนด $N$
$$2^{h+1} \approx N \implies \mathbf{h \approx \lfloor \log_2 N \rfloor}$$ นี่คือเหตุผลที่โครงสร้างต้นไม้สมดุลค้นหาข้อมูลได้เร็วระดับ $O(\log N)$

การขยายขนาดอาร์เรย์แบบทวีคูณ (Dynamic Array Doubling)

STRATEGY ทำไม Python list และ Java ArrayList ถึงขยายขนาดเป็น 2 เท่า?
เมื่ออาร์เรย์เต็ม จะจองหน่วยความจำใหม่ขนาด $2 \times \text{เดิม}$ แล้ว Copy ข้อมูลเดิมไปวาง:
ขนาดที่ขยาย: $1 \to 2 \to 4 \to 8 \to 16 \to \dots \to N$
ต้นทุนการ Copy ทั้งหมดคือผลรวมอนุกรมเรขาคณิต: $$\mathbf{1 + 2 + 4 + 8 + \dots + \frac{N}{2} = N - 1 < N}$$
AMORTIZED ต้นทุนถัวเฉลี่ย (Amortized Analysis)
นำต้นทุนรวมทั้งหมดหารด้วยจำนวนข้อมูล $N$ ตัว: $$\mathbf{\text{Amortized Cost} = \frac{\text{ต้นทุนรวม}}{N} = \frac{O(N)}{N} = O(1)}$$ ทำให้การ `append()` มีความเร็วเฉลี่ยระดับ **Constant Time $O(1)$**
CONTRAST ถ้าขยายทีละ 1 ช่องล่ะ?
ต้นทุนจะเป็นอนุกรมเลขคณิต:
$1 + 2 + 3 + \dots + N = \frac{N(N+1)}{2} \implies O(N^2)$
ถัวเฉลี่ยต่อตัวจะกลายเป็น $O(N)$ ซึ่ง **ช้ากว่าอย่างมหาศาล!**

Concept 5.1

นิยามฟังก์ชันเวียนเกิดและโครงสร้าง 2 ส่วนสำคัญ

ANALOGY มโนภาพในชีวิตจริง: ยอดเงินในบัญชีดอกเบี้ยทบต้น (Compound Interest)
สมมุติยอดเงินในบัญชีสิ้นปีที่ $n$ คือ $B(n)$ โดยได้ดอกเบี้ยทบต้น $10\%$ ต่อปี ($1.10$) จากเงินต้นตั้งต้น 10,000 บาท:
• ขั้นตอนเวียนเกิด (Recursive Step): $B(n) = B(n - 1) \times 1.10$ (ยอดเงินปีนี้คำนวณจากยอดเงินปีก่อนหน้า)
• กรณีฐาน (Base Case): $B(0) = 10,000$ บาท (หากไม่มีเงินต้นตั้งต้น เราจะไม่สามารถคำนวณยอดเงินปีใดๆ ได้เลย!)
PART 1 1. กรณีฐาน (Base Case)
• เงื่อนไขการหยุดการเรียกซ้ำ ที่ส่งค่าผลลัพธ์กลับได้ทันทีโดยไม่ต้องคำนวณต่อ เช่น $n \le 1$
• คำเตือนสำคัญ: หากลืมกำหนด Base Case โปรแกรมจะเรียกตัวเองไม่รู้จบจนเกิด Stack Overflow Error!
PART 2 2. ขั้นตอนเวียนเกิด (Recursive Step)
• ส่วนที่ฟังก์ชันเรียกตัวเองด้วยขนาดปัญหาที่เล็กลง เช่น $f(n-1)$ หรือ $f(n/2)$
• ต้องรับประกันว่าทุกการเรียกซ้ำจะมีทิศทางเคลื่อนที่เข้าใกล้ **Base Case** เสมอ

def factorial(n):

ตัวอย่างที่ 12 — ลำดับฟีโบนัชชี ต้นไม้การเรียกซ้ำ และ DP

DEF สมการเวียนเกิดฟีโบนัชชี
$$F_0 = 0, \quad F_1 = 1, \quad \mathbf{F_n = F_{n-1} + F_{n-2} \quad (n \ge 2)}$$
NAIVE ปัญหา Overlapping Subproblems ($O(2^n)$)
การเรียกซ้ำแบบธรรมดาจะคำนวณค่าเดิมซ้ำมหาศาล เช่น $F_3$ ถูกคำนวณซ้ำหลายรอบ ทำให้เวลาพุ่งเป็น $O(2^n)$
MEMO การแก้ปัญหาด้วย Memoization / DP ($O(n)$)
จดจำผลลัพธ์ที่คำนวณแล้วไว้ในตาราง (Array / Dict): 
def fib(n, memo={}):
    if n in memo: return memo[n]
    if n <= 1: return n
    memo[n] = fib(n-1, memo) + fib(n-2, memo)
    return memo[n]
ลดเวลาจาก $O(2^n)$ เหลือเพียง **$O(n)$** อย่างมหัศจรรย์!

ALGO ขั้นตอนวิธีแก้ปัญหาฮานอยสำหรับ $n$ แผ่น
1. ย้ายแผ่นจาน $n - 1$ แผ่นบน จากเสา A ไปเสา B (เสาพัก)
2. ย้ายแผ่นจานที่ใหญ่ที่สุดแผ่นที่ $n$ จากเสา A ไปเสา C (เสาเป้าหมาย)

RECURRENCE การสร้างและแก้สมการเวียนเกิด
